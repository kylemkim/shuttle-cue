# 🏸 Shuttle Cue PWA v1.4 — Sky Blue Combination Edition

갤럭시 Z Flip 5에서 Chrome으로 설치할 수 있는 개인용 배드민턴 훈련 PWA입니다. HTML/CSS/JavaScript로만 동작하며, 계정·서버·DB·분석 추적은 사용하지 않습니다.

**이미 GitHub Pages에 v1.3을 배포한 경우에는 새 저장소를 만들지 마세요.** 같은 `shuttle-cue` 저장소에 v1.4 파일을 업로드하면 기존 주소(`https://kylemkim.github.io/shuttle-cue/`)에서 업데이트할 수 있습니다.

## 1. 모드

| 모드 | 신호 | 주요 설정 |
| --- | --- | --- |
| A. Reaction | 무작위 비프음 | 최소·최대 신호 간격 0.1~5.0초, 음량 |
| B. Footwork | 선택 언어의 8방향 음성 | 방향 선택, 중앙 복귀 시간, 추가 랜덤 대기 |
| C. Grip | 1~10 숫자 음성 | 그립 번호 선택, 최소·최대 신호 간격 |
| **D. Combo (신규)** | **방향 → 스트로크의 2단계 음성** | 방향별 스트로크 선택, 단계 간 지연, 중앙 복귀 시간, 추가 랜덤 대기 |

모든 시간 슬라이더는 0.1초 단위이며, 값 옆의 ±0.1 버튼으로 미세 조절할 수 있습니다. 모든 음성 모드는 English (US, 기본), 한국어, 日本語를 지원합니다. 음성 속도 기본은 1.2배이고 0.8~1.6배로 변경 가능합니다. A의 비프음은 언어 설정의 영향을 받지 않습니다.

## 2. D. Combo 기본 조합 (오른손잡이 기준)

| 풋워크 방향 | 선택 가능한 스트로크 | 기본 선택 |
| --- | --- | --- |
| 왼쪽 앞 | 백핸드 언더, 백핸드 푸쉬, 헤어핀 | 3개 모두 |
| 정면 | 포핸드 언더, 백핸드 언더, 포핸드 푸쉬, 백핸드 푸쉬, 헤어핀 | 5개 모두 |
| 오른쪽 앞 | 포핸드 언더, 포핸드 푸쉬, 헤어핀 | 3개 모두 |
| 오른쪽 사이드 | **포핸드 드라이브만** | 선택 |
| 왼쪽 사이드 | **백핸드 드라이브만** | 선택 |
| 오른쪽 뒤 | 클리어, 스매시, 드롭 | 3개 모두 |
| 뒤 | 클리어, 스매시, 드롭 | 3개 모두 |
| 왼쪽 뒤 | 클리어, 스매시, 드롭, **백핸드 클리어** | 4개 모두 |

총 **23개 방향-스트로크 조합**에서 시작합니다. 코너 카드를 펼쳐 체크박스를 끄거나 켜면 해당 조합의 출제 여부가 바뀝니다. 한 방향의 체크를 모두 끄면 그 방향은 제외됩니다. 전체 선택이 0개이면 시작을 차단합니다. `추천 조합 복원`은 D의 조합만 기본값으로 돌립니다.

* 정면의 다섯 동작과 뒤쪽 코너의 오버헤드 동작은 실사용을 위해 제안한 기본값입니다. 본인의 훈련 스타일에 맞게 체크를 조절하세요.
* `C-2`, `C-7`, `C-3`, `C-8`, `C-5`, `C-10` 표시가 있으면 기존 C.Grip의 숫자 번호에 연결되는 스트로크라는 뜻입니다. **C의 숫자 1~10 대응은 변경되지 않았습니다.**
* '헤어핀', '클리어', '스매시', '드롭', '백핸드 클리어'는 D에 새로 추가한 동작 이름입니다.
* D 모드는 방향/동작 **음성**을 읽으며 숫자 암기는 필요 없습니다.

### 2단계 음성의 정확한 타이밍

기본값: 방향 안내 → (방향 **음성 종료 후** 0.7초 지연) → 스트로크 안내 → (스트로크 **음성 종료 후** 중앙 복귀 2.0초 + 무작위 대기 1.0~3.0초) → 다음 방향 안내.

예시: `Front Right` → `Forehand Push` → 복귀 → `Back Left` → `Backhand Clear`.

- 첫 방향 신호는 시작 카운트다운 후 랜덤 1~3초 뒤 발생합니다.
- 방향에서 스트로크까지의 지연: **0.0~2.0초**, 0.1초 단위.
- D의 복귀 시간: **0.0~8.0초**, 0.1초 단위. 기존 B의 복귀 설정과 별도로 저장됩니다.
- 추가 랜덤 대기: **0.1~5.0초**에서 최소/최대 설정.
- **방향 음성과 스트로크 음성을 중첩하지 않습니다.** TTS 종료 신호를 기다리며, 브라우저가 종료 이벤트를 보내지 않는 경우 최대 6초 후 다음 단계로 진행합니다.
- 직전과 같은 방향+스트로크 조합을 피하는 옵션(기본 ON) 제공. 단 하나의 조합만 선택했다면 반복됩니다.
- D의 신호 횟수는 방향+스트로크 **한 세트를 1회**로 계산합니다.
- 훈련 시간이 두 단계 사이에 끝나면 마지막 스트로크까지 들려준 후 종료합니다. 따라서 표시 시간은 00:00이어도 잠시 종료 중일 수 있습니다.
- 일시정지 또는 화면 전환 시 TTS를 중단합니다. 재개 시 해당 단계의 음성을 처음부터 다시 읽되, 조합 횟수는 중복으로 증가시키지 않습니다.

주의: **설정한 시간은 JavaScript 예약 시간이며 실제 선수 반응 측정값이 아닙니다.** 기기의 TTS 음성 길이, 잠금 상태, 절전 정책 등에 따라 실제 음성 시작 시각은 달라집니다. B/C에서 0.1초 같은 극단적으로 짧은 간격을 선택하면 이전 음성이 잘릴 수 있습니다. A/B/C의 기존 동작은 그대로입니다.

## 3. 소스 구조

```text
shuttle-cue/
├── index.html          # 화면 구조, A/B/C/D 탭
├── styles.css          # 밝은 파스텔 하늘색 디자인, 반응형 레이아웃
├── app.js              # 상태 머신, 랜덤 출제, 음성, 선택 조합, 설정 저장
├── manifest.webmanifest # PWA 설치용 이름, 아이콘, 시작 URL
├── service-worker.js   # v1.4 버전의 앱 파일 오프라인 캐시
├── icons/
│   ├── icon.svg
│   ├── icon-192.png
│   └── icon-512.png
├── README_KO.md
└── DEPLOY_GUIDE_KO.md
```

앱 내부 저장값은 `localStorage`의 `shuttle-cue-settings-v1.4`에 보관됩니다. 기존 v1.3/v1.2/v1.1의 훈련 시간, 언어, 속도, A/B/C 무작위 간격 등 가능한 값을 자동 복원합니다. 최초 실행 시 D는 추천 23조합으로 초기화합니다. 데이터는 서버가 아닌 **해당 브라우저/설치된 앱의 로컬 저장소**에만 저장됩니다.

## 4. 이미 배포한 GitHub Pages에 v1.4 업로드

1. [shuttle-cue GitHub 저장소](https://github.com/kylemkim/shuttle-cue)를 PC에서 엽니다.
2. 다운로드한 `Shuttle_Cue_PWA_v1.4.zip`을 압축 해제합니다.
3. 저장소 `Code` 탭 → **Add file → Upload files**.
4. 압축 해제한 폴더 **안쪽의 앱 파일과 `icons/` 폴더**를 선택하여 업로드합니다. ZIP 파일 자체나 상위 폴더째 업로드하지 마세요.
5. 기존 `index.html`, `app.js`, `styles.css`, `service-worker.js` 등이 같은 위치에서 교체되는지 확인합니다. 파일명을 바꾸지 마세요.
6. **Commit changes**를 누릅니다.
7. `Actions`에서 `pages build and deployment`가 성공했는지 확인합니다.
8. 기존 주소 [Shuttle Cue 웹앱](https://kylemkim.github.io/shuttle-cue/)을 새로고침합니다. 앱 아래쪽 `v1.4 · PWA`와 D. Combo 탭을 확인합니다.
9. 설치한 갤럭시 앱이 구버전이면 앱을 완전히 종료했다가 다시 열거나 새로고침합니다. 캐시 때문에 잠시 이전 버전이 보일 수 있습니다.

앱 주소, PWA 아이콘, 저장소 이름은 바꿀 필요가 없습니다. `Settings → Pages`는 계속 `main` / `/(root)` 그대로 유지하면 됩니다.

> **업로드 주의**: GitHub 웹 업로드에서 폴더가 원하는 위치로 올라가지 않는다면, 개별 파일과 `icons` 폴더의 경로를 반드시 확인해 주세요. 업로드 후 `index.html`이 `shuttle-cue/index.html` 같은 *중첩 폴더*에 들어갔다면 Pages 루트에서 동작하지 않습니다.

## 5. 갤럭시 Z Flip 5 테스트

1. Chrome에서 https://kylemkim.github.io/shuttle-cue/ 를 엽니다.
2. `D. Combo` 모드를 선택합니다. 왼쪽 앞, 정면, 왼쪽 뒤 카드에서 선택 가능한 스트로크가 보이는지 확인합니다.
3. `음성 테스트`를 눌러 영어 방향 → 짧은 지연 → 영어 스트로크가 들리는지 확인합니다.
4. English / 한국어 / 日本語를 각각 선택하고 테스트합니다.
5. D의 복귀 2.0초, 랜덤 1.0~3.0초, 지연 0.7초로 30초 정도 훈련해 봅니다.
6. 훈련 중 **일시정지**, **이어하기**, **종료**를 시험합니다.
7. A/B/C도 각각 한 번씩 시험해 기존 기능을 확인합니다.
8. Wi-Fi를 끊고 오프라인 실행을 확인할 때는 먼저 온라인 상태에서 앱 파일 캐시가 만들어져 있어야 합니다. 오프라인 TTS 음성은 설치된 언어 음성 데이터에 따라 작동하지 않을 수도 있습니다.

## 6. 알려진 제한

- 안드로이드 Chrome의 TTS 목소리와 타이밍은 PC 브라우저와 다를 수 있습니다. 오프라인 한국어·일본어·영어 음성은 각 언어 TTS 데이터의 설치 상태에 영향을 받습니다.
- 화면이 꺼지거나 다른 앱으로 전환되면 자동 일시정지하며, 잠금 화면 재생 및 백그라운드 연속 훈련은 지원하지 않습니다.
- `D`는 사용자가 선택한 조합 중 **균등 확률**로 출제합니다. 코너별 확률 가중치와 선수 동작 평가/카메라 인식은 포함되지 않았습니다.
- 훈련 결과는 신호 횟수만 표시하며, 정확도/반응시간/스윙 품질은 측정하지 않습니다.
- 사용자는 훈련 장소에서 미끄럼·부딪힘 위험을 확인하고, 충분한 공간과 체력에 맞춰 진행해야 합니다.

## 7. 개발자가 읽는 구현 메모

- `DIRECTIONS`는 방향 ID와 한국어 표시명을 정의합니다.
- `STROKES`는 영어·일본어·한국어 음성 텍스트와 기존 C 그립 번호 연결을 정의합니다.
- `COMBO_ALLOWED`는 **해당 코너에 나타날 수 있는 선택지**를 정의합니다. 오른쪽/왼쪽 사이드는 드라이브만 있습니다.
- `settings.combination.strokes[directionId]`는 사용자가 체크한 스트로크 ID 목록입니다.
- `selectedCombinations()`가 실제 랜덤 출제 가능한 `(direction,stroke)` 쌍을 반환합니다.
- `beginComboDirection()`은 조합을 뽑고 방향을 읽습니다. 음성이 끝나면 `comboPhase='gap'`으로 전환합니다.
- `deliverComboStroke()`는 `delay` 뒤 스트로크를 읽습니다. 음성이 끝나면 `comboPhase='waiting'`으로 전환해 `recovery + randomSeconds()` 대기를 예약합니다.
- `performance.now()`를 기준으로 예약하고, `setInterval(...,25)`는 예약 시각 도달 여부를 확인합니다. 따라서 호출 주기 25ms와 실제 TTS 지연은 구별해야 합니다.
- 일시정지는 현재 남은 시간을 저장하고 TTS를 취소하며, `sequenceToken`을 증가시켜 이전 음성 콜백이 재개 뒤 실행되지 않도록 방지합니다.
